# Доказательства прогона

Все файлы относятся к версии `5c663ea7eadbbd830f438680f556f13639cfaecc`.
Дата проверки — 17.10.2026. Данные синтетические, запросы направлялись
только в отдельное локальное приложение задач.

| Файл | Что подтверждает |
| --- | --- |
| [environment.json](environment.json) | Версию, окружение, команду запуска и SHA-256 проверенного JAR |
| [openapi-observed.json](openapi-observed.json) | Контракт, полученный с работающего сервера; сравнение с файлом проекта — HTTP-01 |
| [http-checks.json](http-checks.json) | 85 пунктов и фактические HTTP-события, включая подготовку, чтение до/после и очистку |
| [defect-repeats.json](defect-repeats.json) | 18 повторов: 3 дефекта × 2 метода × 3 попытки |
| [ui-checks.json](ui-checks.json) | 13 проверок в веб-интерфейсе и ссылки на текстовые снимки |
| [lifecycle.json](lifecycle.json) | Наличие задач до перезапуска и пустое хранилище после него |
| [checklist-results.json](checklist-results.json) | Все 102 пункта и итоговые счётчики |
| [reproduce-BUG-001.txt](reproduce-BUG-001.txt), [BUG-002](reproduce-BUG-002.txt), [BUG-003](reproduce-BUG-003.txt) | Фактический вывод готовых команд воспроизведения для обоих методов |

В `http-checks.json` поле `checks` содержит критерий, результат, дефект и
`eventRange`. Это включительный диапазон индексов массива `events`, начиная с нуля.
В событии записаны метод, путь, заголовки, тело запроса, HTTP-статус и фактический
ответ. Невалидный UTF-8 записан массивом байтов. Удаления при подготовке служат
изоляции тестовых данных и не являются отдельными пунктами чек-листа.
События `check=defect-repeat` относятся к повторным воспроизведениям.
В текстовом выводе curl нормализованы окончания строк и пробелы в конце
строк заголовков для просмотра в GitHub; статусы, значения заголовков
и тела ответов сохранены. В JSON-журнале одно HTTP-событие занимает одну строку.

В `defect-repeats.json` можно отфильтровать `repeats` по `bug`, `method` и `attempt`.
В каждой записи есть `expectedStatus`, `actualStatus`, `requestBody`, `response`,
`before`, `after`. Счётчики в `metadata.summary` скопированы из основного
HTTP-прогона и не являются числом повторов.

Файлы `ui/*.txt` — полные снимки доступного текста интерфейса, полученные после
действия. Они включают как **Server response**, так и справочные **Responses**.
Результат запроса следует читать в секции **Server response**: примеры схем
в секции Responses сами по себе не подтверждают выполнение запроса.

Числовые ID в снимках принадлежат одному прогону. Для повторения следует получать
свои ID из ответа POST. Перезапуск сбрасывает и данные, и последовательность ID;
старый снимок при этом остаётся доказательством только сохранённого прогона.
