# Практическая работа. Чек-лист и баг-репорты

Проверил приложение задач из лабораторной №2. Его веб-интерфейс — Swagger UI:
через него можно создавать, читать, изменять и удалять задачи. Составил чек-лист,
выполнил проверки на работающем приложении и оформил три воспроизводимых дефекта.

Материалы курса отдельно не приложены. Тестовой базой взял README и OpenAPI
проекта. Применил классы эквивалентности, анализ граничных значений, таблицу
решений и переходы состояний. Дополнительные критерии явно отделил от требований
приложения; соответствие неизвестным материалам курса не заявляю.

## Объект и границы проверки

Проверяемая версия — Tasks API 1.0.0, коммит
`5c663ea7eadbbd830f438680f556f13639cfaecc` из ветки `lab2`.
В этой работе исходный код приложения и существующие API-тесты не изменял.
Версию фиксирую до добавления документации: это позволяет повторить проверку
именно той сборки, на которой нашёл дефекты.

В область проверки включил веб-интерфейс, все пять операций, сохранение значений,
валидацию полей, пагинацию, обработку ошибок и поведение при перезапуске.
Прямые HTTP-запросы использовал для точной подачи граничных и повреждённых данных;
основной пользовательский сценарий и каждый дефект дополнительно проверил
в Swagger UI. По доступности страницы не делал вывод о корректности операций.

В приложении нет собственной HTML-формы задач, регистрации, ролей, поиска,
загрузки файлов или оплаты. Не добавлял эти функции в требования. Потеря данных
после перезапуска — документированное свойство хранилища в памяти, поэтому
баг-репорт на неё не оформлял. Нагрузка, полный аудит безопасности и оценка
доступности по WCAG не входили в этот прогон.

| Контракт | `http://127.0.0.1:18080/openapi.json` |
| Изоляция | Отдельный локальный экземпляр без других пользователей; только тестовые задачи |

SHA-256 проверенного JAR и сведения о запуске сохранены в
[environment.json](evidence/environment.json). Время в JSON-доказательствах
записано в UTC с суффиксом `Z`; местное время на четыре часа больше.

Из корня репозитория собрать приложение и запустить его в отдельном терминале:

```bash
./mvnw -DskipTests package
java -jar target/api-testing-lab2-1.0.0.jar \
  --server.address=127.0.0.1 --server.port=18080
```

Для запуска нужен JDK 21 или 25. Затем открыть адрес Swagger UI из таблицы.
Начальное состояние — пустое хранилище после запуска. В ходе прогона удалял
созданные тестовые задачи между независимыми сценариями. Для проверок пагинации
создал 21 задачу с названиями `Страница 1` … `Страница 21`.
ID всегда получал из ответа; число `173` в UI-доказательствах относится только
к сохранённому прогону. На новом экземпляре ID будут другими.

## Результат прогона

| Часть | Pass | Fail | Not run | Всего |
| --- | ---: | ---: | ---: | ---: |
| Веб-интерфейс | 13 | 0 | 0 | 13 |
| Операции, поля, границы и HTTP | 79 | 6 | 0 | 85 |
| Перезапуск | 1 | 0 | 0 | 1 |
| Дополнительное покрытие | 0 | 0 | 3 | 3 |
| **Итого** | **93** | **6** | **3** | **102** |

Выполнено 99 из 102 пунктов. Шесть Fail относятся к трём причинам:

| Дефект | Наблюдение | Связанные пункты |
| --- | --- | --- |
| [BUG-001](bugs/BUG-001.md) | Некорректное тело с данными после JSON принимается и меняет хранилище | JSON-05, JSON-06 |
| [BUG-002](bugs/BUG-002.md) | Название только из Unicode-пробела принимается вопреки `pattern: \S` | TITLE-18, TITLE-19 |
| [BUG-003](bugs/BUG-003.md) | Допустимое по OpenAPI название из 51–100 одиночных emoji отклоняется | TITLE-15, TITLE-16 |

Каждый дефект повторил три раза для POST и три раза для PUT. Это повторные
воспроизведения, а не дополнительные пункты чек-листа. Сохранил фактические тела
запросов, ответы, состояние до и после запроса и по одному снимку веб-интерфейса
для каждого дефекта. В реестре стоит статус **New**: дефекты обнаружены,
исправления и повторного тестирования исправленной версии ещё не было.

Не выполнял EXT-01 — независимые Chrome и Firefox, EXT-02 — мобильную компоновку,
EXT-03 — сценарий только с клавиатуры. Они отмечены Not run, а не Pass.
Проверки в одном встроенном браузере не подтверждают совместимость со всеми
браузерами и устройствами.

## Оценка результата и следующий шаг

Основные операции работают, но приёмка приложения по выбранным критериям пока
не завершена: BUG-001 нарушает проверку тела запроса и позволяет менять данные
некорректным запросом. BUG-002 и BUG-003 показывают расхождения между контрактом
и серверной валидацией Unicode. Сначала предлагаю исправить BUG-001, затем
согласовать одинаковые правила обработки строк в контракте и приложении.

После исправления нужно повторить связанные Fail-пункты, проверить сохранность
данных при отклонении POST/PUT и выполнить регрессию основного CRUD-сценария.
Критерий завершения основной приёмки: нет открытых S1/S2 и Fail с приоритетом P1,
все 99 пунктов основного прогона выполнены с ожидаемым результатом.
Это предложенный критерий этой практической работы, а не условие, приписанное
преподавателю. Документация фиксирует найденные дефекты; их исправление в задание
по составлению чек-листа и баг-репортов не включено.
