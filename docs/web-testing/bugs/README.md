# Реестр дефектов

Проверяемая версия: Tasks API 1.0.0,
`5c663ea7eadbbd830f438680f556f13639cfaecc`. Дата: 17.10.2026.
Статус всех трёх записей — **New**. Назначение исполнителя и сроки не согласованы.

| ID | Краткое описание | Severity | Priority | Проверки |
| --- | --- | --- | --- | --- |
| [BUG-001](BUG-001.md) | Данные после первого JSON-объекта игнорируются, запрос меняет хранилище | S2 Major | P1 | JSON-05, JSON-06 |
| [BUG-002](BUG-002.md) | Название из Unicode-пробела принимается вопреки контракту | S3 Minor | P2 | TITLE-18, TITLE-19 |
| [BUG-003](BUG-003.md) | Название из 51–100 одиночных emoji отклоняется при maxLength=100 | S2 Major | P2 | TITLE-15, TITLE-16 |

Severity описывает влияние: S1 Critical — основной сценарий целиком недоступен
или данные массово теряются; S2 Major — нарушена значимая функция или контракт
записи; S3 Minor — ограниченный дефект без остановки основного сценария;
S4 Trivial — косметическое отклонение. Priority задаёт порядок исправления:
P1 — в первую очередь, P2 — следующим этапом, P3 — при наличии ресурса.
Эта шкала выбрана для работы; её не выдаю за стандарт конкретной команды.

Несколько вариантов одного отклонения объединил в один отчёт: POST и PUT,
двойной объект и мусор после объекта, разные Unicode-пробелы, длины 51 и 100.
Поэтому шесть Fail в чек-листе соответствуют трём дефектам, а не шести.

Дефекты повторены три раза на POST и три раза на PUT. Доказательства повторов —
[defect-repeats.json](../evidence/defect-repeats.json), снимки и фактические ответы
приложены к каждому отчёту. Исправления в исходный код в рамках этой работы
не вносились, поэтому статус Fixed или Closed не использован.
