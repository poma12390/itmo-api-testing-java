# BUG-001. Запрос с данными после JSON-объекта принимается

| Поле | Значение |
| --- | --- |
| Статус | New |
| Методы | POST `/tasks`, PUT `/tasks/{taskId}` |
| Severity / Priority | S2 Major / P1 — повреждённый запрос создаёт или заменяет задачу |
| Повторяемость | POST 3/3, PUT 3/3; также в Swagger UI |
| Проверки | JSON-05, JSON-06; R-10 |

Версия и окружение — в [отчёте](../README.md). Для PUT нужна существующая задача.

## Шаги

1. В Swagger UI раскрыть POST `/tasks` и нажать **Try it out**.
2. Вставить два объекта подряд и нажать **Execute**:

   ```text
   {"title":"Первый объект"}{"title":"Второй объект"}
   ```

3. Прочитать задачу по Location из ответа.
4. Отправить то же тело через PUT существующей задачи и снова прочитать её.

Повторить через curl:

```bash
curl -i -X POST http://127.0.0.1:18080/tasks \
  -H 'Content-Type: application/json' \
  --data-binary @docs/web-testing/fixtures/bug-001-trailing-object.txt
```

## Ожидание и результат

Ожидал **400**, `field=body`, без изменения данных: JSON должен содержать одно
корневое значение ([RFC 8259, §2](https://www.rfc-editor.org/rfc/rfc8259.html#section-2)).

Получил **201** на POST и **200** на PUT. Сохранились данные первого объекта,
второй был проигнорирован. GET подтвердил запись. Ответ POST из браузера:

```json
{"id":174,"title":"Первый объект","priority":3,"completed":false}
```

То же происходит с `{"title":"До мусора"}oops`. Возможная причина — Jackson
не проверяет остаток после первого значения; в `JacksonConfig` не включён
`FAIL_ON_TRAILING_TOKENS`.

## Повторная проверка

Оба варианта должны отклоняться с 400 на POST и PUT, не меняя данные.
Обычные пробелы после корректного объекта должны оставаться допустимыми.
