# BUG-002. Сохраняется название из Unicode-пробела

| Поле | Значение |
| --- | --- |
| Статус | New |
| Методы | POST `/tasks`, PUT `/tasks/{taskId}` |
| Severity / Priority | S3 Minor / P2 — задача получает визуально пустое название |
| Повторяемость | U+00A0: POST 3/3, PUT 3/3; также в Swagger UI |
| Проверки | TITLE-18, TITLE-19; R-06 |

Версия и окружение — в [отчёте](../README.md). Для PUT нужна существующая задача.

## Шаги

1. В Swagger UI раскрыть POST `/tasks`, нажать **Try it out**.
2. Вставить тело с escape-последовательностью и нажать **Execute**:

   ```json
   {"title":"\u00a0"}
   ```

3. Прочитать задачу по Location. В title должен быть один U+00A0, а не текст `\u00a0`.
4. Повторить через PUT для существующей задачи и прочитать её снова.

```bash
curl -i -X POST http://127.0.0.1:18080/tasks \
  -H 'Content-Type: application/json' \
  --data-binary @docs/web-testing/fixtures/bug-002-nbsp.json
```

## Ожидание и результат

Ожидал **422**, `field=title`, без изменения данных. В OpenAPI у title задан
`pattern: \S`. U+00A0 считается пробелом в
[ECMA-262](https://tc39.es/ecma262/multipage/ecmascript-language-lexical-grammar.html#sec-white-space),
синтаксис которой используется в
[JSON Schema](https://json-schema.org/draft/2020-12/json-schema-validation#section-6.3.3).

Получил **201** на POST и **200** на PUT. Название сохранилось; GET подтвердил
результат. Невидимый символ в ответе показан экранированием:

```json
{"id":175,"title":"\u00a0","priority":3,"completed":false}
```

Та же ошибка есть для U+2003 (EM SPACE). Обычные пробелы, табуляция и перевод
строки отклоняются правильно. Серверная валидация и контракт по-разному
определяют пробельные символы.

## Повторная проверка

Названия только из U+00A0 или U+2003 должны давать 422 на POST и PUT.
Текст с пробелами по краям должен приниматься.
