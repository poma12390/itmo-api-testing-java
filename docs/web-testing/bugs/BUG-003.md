# BUG-003. Название из 51–100 одиночных emoji отклоняется при maxLength=100

| Поле | Значение |
| --- | --- |
| Статус | New |
| Тип | Функциональный дефект: длина Unicode-строки / расхождение с контрактом |
| Компонент | `TaskRequest.title`; POST `/tasks`, PUT `/tasks/{taskId}` |
| Версия | Tasks API 1.0.0, коммит `5c663ea7eadbbd830f438680f556f13639cfaecc` |
| Обнаружен | 17.10.2026 |
| Окружение | macOS 26.7.1, Java 25.0.2; встроенный браузер, 1280×720; `127.0.0.1:18080` |
| Severity | S2 Major: сервер блокирует создание и замену задач с допустимым по контракту названием |
| Priority | P2: затронут ограниченный класс Unicode-строк; сначала BUG-001 |
| Повторяемость | 51 × U+1F600: POST 3/3 и PUT 3/3; дополнительно воспроизведён в Swagger UI |
| Связанные проверки | TITLE-15, TITLE-16; требование R-06 |

## Предусловия

Запущен экземпляр проверяемой версии по [инструкции](../README.md).
В `TaskRequest.title` указаны `minLength=1`, `maxLength=100`, `pattern=\S`.
Для PUT заранее создана задача, её id получен из ответа.
Входные данные — [готовое тело с 51 emoji](../fixtures/bug-003-emoji-51.json).
Каждый emoji в нём — одиночный символ U+1F600, без модификаторов и соединителей.

## Шаги воспроизведения

1. Открыть файл `docs/web-testing/fixtures/bug-003-emoji-51.json` и скопировать его тело.
2. В Swagger UI раскрыть POST `/tasks`, нажать **Try it out**, вставить тело.
3. Нажать **Execute** и посмотреть **Server response**.
4. Повторить тот же запрос в PUT `/tasks/{id}` существующей задачи.
5. Выполнить GET списка и исходной задачи, чтобы проверить сохранённое состояние.

Точный запрос без ручного подсчёта emoji:

```bash
curl -i -X POST http://127.0.0.1:18080/tasks \
  -H 'Content-Type: application/json' \
  --data-binary @docs/web-testing/fixtures/bug-003-emoji-51.json
```

## Ожидаемый результат

POST возвращает **201**, PUT — **200**. Название из 51 кодовой точки укладывается
в `maxLength=100`; последующий GET возвращает его без потери символов.
В [JSON Schema Validation, §6.3.1](https://json-schema.org/draft/2020-12/json-schema-validation#section-6.3.1)
длина определяется символами JSON-строки, а не количеством кодовых единиц UTF-16.

## Фактический результат

Оба метода возвращают **422**:

```json
{"detail":"Validation failed","field":"title"}
```

Новая задача не создаётся, существующая не изменяется. Это подтверждено чтением
состояния до и после запроса. Название из 100 таких emoji также отклоняется.

Контрольные точки основного прогона:

| Название | Кодовые точки | Единицы UTF-16 | POST / PUT | Оценка |
| --- | ---: | ---: | --- | --- |
| 50 × U+1F600 | 50 | 100 | 201 / 200 | Корректно |
| 51 × U+1F600 | 51 | 102 | 422 / 422 | Дефект |
| 100 × U+1F600 | 100 | 200 | 422 / 422 | Дефект |
| 101 × U+1F600 | 101 | 202 | 422 / 422 | Корректно |
| 100 × «я» | 100 | 100 | 201 / 200 | Корректно |
| 101 × «я» | 101 | 101 | 422 / 422 | Корректно |

## Влияние и диагностика

Клиент может считать название валидным по OpenAPI, но сервер откажет в записи.
Ограничение фактически зависит от представления символов, хотя контракт этого
различия не описывает. Данные не теряются, но часть допустимых задач нельзя создать.

Гипотеза причины: `@Size(max=100)` проверяет длину Java-строки в кодовых единицах
UTF-16. Сравнение 50 и 51 повторов согласуется с этой гипотезой. Исправление
не вносил; итоговое решение должно согласовать ограничение сервера и контракт.

101 отклоняется с 422 без изменения данных. Дополнительно проверить смешанное
название из BMP-символов и U+1F600, а также прежние границы кириллицей.
