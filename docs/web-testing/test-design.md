# Тестовая база и тест-дизайн

## Требования и прослеживаемость

Идентификаторы R введены в этой работе, чтобы связать тестовую базу с чек-листом.
Содержательные правила R-01–R-12 взяты из README и OpenAPI версии
`5c663ea7eadbbd830f438680f556f13639cfaecc`. R-13 описывает проверяемое использование
веб-оболочки Swagger UI. Это не номера требований из курса.

| ID | Проверяемое правило | Источник | Покрытие в чек-листе |
| --- | --- | --- | --- |
| R-01 | Приложение публикует актуальный контракт OpenAPI 3.1 с пятью операциями | README, `openapi.json`: `openapi`, `paths` | HTTP-01 |
| R-02 | POST создаёт задачу, выдаёт положительный id и Location; GET возвращает сохранённые поля | README: «API»; POST/GET в OpenAPI | CRUD-01–CRUD-05 |
| R-03 | Отсутствующие priority и completed получают 3 и false | README; `TaskRequest` | CRUD-03, CRUD-07 |
| R-04 | PUT заменяет задачу полностью и сохраняет её id; повтор не создаёт ещё одну задачу | README; PUT `/tasks/{taskId}` | CRUD-06–CRUD-08, CRUD-12 |
| R-05 | DELETE существующей задачи возвращает 204 с пустым телом; удалённая недоступна | README; DELETE/GET в OpenAPI | CRUD-09–CRUD-11 |
| R-06 | title обязателен; строка 1–100 символов, содержит непробельный символ | README; `TaskRequest.title`: required, minLength, maxLength, pattern | TITLE-01–TITLE-20 |
| R-07 | priority — JSON-число с целым значением 1–5; строки, дроби, null и другие типы не принимаются | README; `TaskRequest.priority` | PRIORITY-01–PRIORITY-14 |
| R-08 | completed — boolean; строка, число, null, массив и объект не принимаются | README; `TaskRequest.completed` | BOOL-01–BOOL-07 |
| R-09 | taskId — положительный int64; невалидный параметр даёт 422 с field; неизвестный допустимый id — 404 | README; параметры и ответы OpenAPI | ID-01–ID-06, CRUD-10–CRUD-12 |
| R-10 | Повреждённый JSON и неверный UTF-8 дают 400; лишние поля — 422; неподдерживаемый метод — 405 с Allow | README: «Тесты»; `additionalProperties`, ответы OpenAPI | JSON-01–JSON-07, HTTP-03–HTTP-04 |
| R-11 | limit: 1–100, по умолчанию 20; offset ≥0, по умолчанию 0; порядок создания; за концом списка — [] | README; GET `/tasks`, параметры int32 | PAGE-01–PAGE-15 |
| R-12 | Хранилище в памяти очищается при перезапуске | README: «API» | STORE-01 |
| R-13 | Через Swagger UI доступны операции, редактор запроса и фактические ответы сервера | README: адрес Swagger UI; критерий проверки веб-оболочки | UI-01–UI-13 |

Негативные операции дополнительно проверяются на отсутствие побочного изменения
хранилища. Корректность результата проверяется по status, полям и последующему
чтению, а не только по отсутствию ошибки на странице.

Отдельные дополнительные критерии:

| ID | Критерий | Основание и статус |
| --- | --- | --- |
| A-01 | Основной сценарий работает в независимых Chrome и Firefox | Предложенное расширение совместимости; EXT-01, Not run |
| A-02 | Поля и кнопки доступны при ширине 360 CSS px | Предложенное расширение проверки интерфейса; EXT-02, Not run |
| A-03 | Основной сценарий доступен с клавиатуры | Предложенное расширение доступности; EXT-03, Not run |
| A-04 | `Content-Type: text/plain` отклоняется с 415 без создания задачи | Дополнительная HTTP-проверка; HTTP-02, Pass; не проверял для неё схему ApiError, так как 415 отсутствует в OpenAPI |

## Классы эквивалентности

| Поле / вход | Допустимые классы | Недопустимые классы | Примеры |
| --- | --- | --- | --- |
| title | Непустая строка допустимой длины с непробельным символом | Нет поля, null, пустая/пробельная строка, превышение длины, иной тип | `Я`, `Задача 😀`, `""`, U+00A0, `123`, `[]`, `{}` |
| priority | Целое значение в интервале; поле отсутствует | Значение вне интервала, дробь, null, иной тип | `1`, `5`, `4.0`, `1e0`, `0`, `6`, `2.5`, `"3"` |
| completed | true, false, поле отсутствует | null и иной тип | `true`, `false`, `"false"`, `1`, `[]`, `{}` |
| taskId | Существующий положительный id; отсутствующий положительный id | Неположительное число, дробь, текст, переполнение int64 | ID из POST, `9223372036854775807`, `0`, `abc` |
| Тело запроса | Один JSON-объект со схемой TaskRequest | Обрыв, неверная кодировка, дополнительные данные после объекта, лишнее поле | `{"title":`, два объекта, `oops` после объекта |

Проверки типов не смешивал с отсутствием значения: отсутствие необязательного поля
и явный null — разные классы. Целое значение `4.0` не относил к ошибкам только
из-за десятичной записи: это допустимый integer в JSON Schema и в README.

## Анализ граничных значений

| Ограничение | Проверенные точки | Смысл |
| --- | --- | --- |
| Длина title 1–100 | 0, 1, 99, 100, 101 | Обе границы и соседние значения |
| Строки вне BMP | 50, 51, 100, 101 повторов U+1F600 | Различить кодовые точки Unicode и кодовые единицы UTF-16 |
| priority 1–5 | 0, 1, 5, 6; дополнительно -1 | Значения на границах и за ними |
| limit 1–100 | 0, 1, 100, 101 | Нижняя и верхняя границы |
| offset | -1, 0, 1, N=21, 2147483647, 2147483648 | Минимум, смещение, конец списка, предел int32 и переполнение |
| taskId | -1, 0, существующий положительный; максимум int64 и значение за ним | Ограничение положительности и представления параметра |

В заголовках с emoji считал кодовые точки, а не визуальные графемы. Каждый
использованный `😀` — ровно U+1F600: 51 повтор — 51 кодовая точка и 102 кодовые
единицы UTF-16. Это не строка из 102 символов по JSON Schema.
Проверки только кириллицей не выявили бы этот дефект.

## Таблица решений для тела запроса

Остальные поля в каждой строке валидны. При нескольких ошибках сразу не требую
конкретного порядка их перечисления: такой порядок в контракте не задан.

| Правило | title | priority | completed | Ожидание |
| --- | --- | --- | --- | --- |
| D1 | Валиден | Отсутствует | Отсутствует | POST 201 / PUT 200, значения 3 и false |
| D2 | Валиден | Валиден | Валиден | Успех, сохранены переданные значения |
| D3 | Невалиден или отсутствует | Любой допустимый | Любой допустимый | 422, field=title, состояние не меняется |
| D4 | Валиден | Невалиден, включая null | Допустим | 422, field=priority, состояние не меняется |
| D5 | Валиден | Допустим | Невалиден, включая null | 422, field=completed, состояние не меняется |
| D6 | Валиден | Допустим | Допустим, но есть лишнее поле id | 422, field=id, состояние не меняется |
| D7 | Тело не является корректным JSON-текстом | — | — | 400, field=body, состояние не меняется |

## Переходы состояний

| Исходное состояние | Действие | Ожидаемое состояние и наблюдение |
| --- | --- | --- |
| Задачи нет | POST валидного тела | Задача существует, получен новый id |
| Задача существует | GET | То же состояние; возвращены сохранённые данные |
| Задача существует | PUT валидного тела | Задача заменена; id и число задач прежние |
| completed=false / true | PUT с противоположным completed | Boolean меняется; дополнительных статусов процесса в модели нет |
| Задача существует | PUT невалидного тела | Предыдущее состояние и поля сохраняются |
| Задача существует | DELETE | Задача отсутствует, 204 без тела |
| Задачи нет | GET / PUT / DELETE | 404; задача не создаётся |
| Есть задачи в процессе | Перезапуск приложения | Пустое хранилище — ожидаемое поведение |

Создание, чтение, замена и удаление проверены также последовательно через
веб-интерфейс. Изолированные HTTP-проверки позволяют не зависеть от результатов
предыдущего негативного сценария.

## Приоритизация и ограничения

Сначала проверил CRUD и данные, затем валидацию и границы, после — пагинацию
и представление ответов в браузере. Приоритет P1 получил риск потери или
некорректного изменения данных; P2 — пагинация и удобство работы с интерфейсом.
Severity и priority самих дефектов назначены отдельно в [реестре](bugs/README.md).

Покрытие требований означает наличие конкретных проверок каждого R-пункта,
но не доказывает отсутствие всех дефектов. Комбинаторный перебор всех строк,
конкурентный доступ, длительная нагрузка и внешние сетевые сбои здесь не проверены.
Дополнительные EXT-проверки оставлены в чек-листе с честным статусом Not run.
