## Запуск

Нужен JDK 21 или 25. Maven Wrapper сам скачает Maven и зависимости:

```bash
./mvnw verify
```

На Windows: `mvnw.cmd verify`. Тесты поднимают приложение на свободном локальном
порту. Внешние API и отдельный запуск сервера не нужны.

Для ручной проверки:

```bash
./mvnw spring-boot:run
```

```bash
curl -i -X POST http://localhost:8080/tasks \
  -H 'Content-Type: application/json' \
  -d '{"title":"Сдать лабораторную","priority":2}'
```

Swagger UI: `http://localhost:8080/swagger-ui/index.html`.
OpenAPI: `http://localhost:8080/openapi.json`.

## API

| Метод | Путь | Успешный ответ |
| --- | --- | --- |
| POST | `/tasks` | `201`, задача и заголовок Location |
| GET | `/tasks?limit=20&offset=0` | `200`, список задач |
| GET | `/tasks/{taskId}` | `200`, задача |
| PUT | `/tasks/{taskId}` | `200`, заменённая задача |
| DELETE | `/tasks/{taskId}` | `204`, пустое тело |

Название обязательно: от 1 до 100 символов, хотя бы один непробельный.
Приоритет — целое число от 1 до 5, по умолчанию 3. Признак выполнения — boolean,
по умолчанию false. Строки вместо чисел и boolean, null и лишние поля отвергаются.
Число `4.0` принимается как целое `4` по правилам JSON Schema.

PUT полностью заменяет задачу. Если priority и completed не переданы, они получают
значения по умолчанию. Данные хранятся в памяти и пропадают после перезапуска.

## Тесты

| Сценарий | Проверка |
| --- | --- |
| Создание, чтение, замена, удаление | Статусы, тело, заголовки и сохранённые данные |
| Пагинация | Порядок, размер страницы, смещение за конец списка |
| Граничные значения | Длины 1/100, приоритеты 1/5, limit 1/100, offset 0 |
| Невалидные данные | Пустые и длинные строки, отсутствующие поля, null, неверные типы |
| Невалидные параметры | Неположительные ID, строки вместо чисел, неправильная пагинация |
| Повреждённый JSON и неверный UTF-8 | `400`, данные не меняются |
| Несуществующая задача | `404` для GET, PUT и DELETE |
| Неподдерживаемый метод | `405` и заголовок Allow |
| OpenAPI | Соответствие запросов и ответов спецификации, актуальность файла |

Ошибки валидации возвращают `422` с названием поля. Каждый сценарий начинает
работу с пустым хранилищем. После отклонённых запросов проверяю состояние данных.

## OpenAPI

Springdoc генерирует спецификацию из Java-моделей, контроллера и аннотаций валидации.
Сохранил её в `openapi.json`. Тест сравнивает файл с контрактом работающего приложения.

`OpenApiGeneratedTest` читает из файла операции, длины строк и числовые ограничения.
По ним создаёт JUnit-тесты для допустимых границ и значений за границами.
REST Assured использует OpenAPI Request Validator для проверки запросов и ответов.
В негативных сценариях проверяю по контракту ответ, поскольку сам запрос заведомо невалиден.

Обновить спецификацию после изменения API:

```bash
./mvnw -Dtest=OpenApiSnapshotTest -DupdateOpenApi=true test
```
